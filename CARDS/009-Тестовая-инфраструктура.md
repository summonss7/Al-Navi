## Задача
Сейчас проверки разрознены: 13 скриптов в `scripts/` (e2e-1-10-0.mjs, e2e-attrs.mjs
и т.д.) запускаются вручную и по одному, юнит-тестов фронтенда нет (чистые функции
типа multiRename.ts проверяются одноразовыми вставками в dev-E2E), cargo test в
этой среде сломан (Rust-логика верифицируется standalone rustc). Нужен единый
вход: `npm test` (или `npm run test:unit` / `test:e2e`), который гоняет устойчивое
ядро проверок, и наведённый порядок в scripts/.

## Критерии готовности
- [ ] Юнит-тесты чистых функций фронтенда (multiRename, format, textColors/fileColors-маски, plugins-конвертер раскладки) на vitest — `npm run test:unit` проходит зелёно из коробки
- [ ] Дымовой E2E-набор (прогон реального exe через CDP: старт, навигация, F5-копия, F8-удаление, редактор F4 сохранить, смена темы/языка) собран в один скрипт с итоговой сводкой pass/fail — `npm run test:e2e`
- [ ] Устаревшие/разовые e2e-скрипты разобраны: актуальные переименованы понятно (e2e-<тема>), одноразовые проверок релизов убраны в scripts/archive/ (не удалять)
- [ ] README: раздел «Проверки» описывает новую команду(ы)
- [ ] Коммит с осмысленным сообщением
