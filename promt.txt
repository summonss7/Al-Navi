## 2026-10-04, 07:47 — Почему проект занимает ~25 ГБ (карточка alnavi-019)

Ответ на вопрос «почему проект занимает 25Гб».

Фактический замер (du): каталог D:\Al-Navi занимает 22 ГиБ = 23,6 десятичных ГБ;
Проводник показывает «размер на диске» (округление кластерами вверх) — отсюда
«~25 ГБ». Суть не в точном числе: 99,5% объёма проекта лежит в одном каталоге
src-tauri\target — кэше компилятора Rust.

Разбивка по каталогам (сверху вниз):
- src-tauri\target — 22 ГБ. Из них:
  - target\debug — 14 ГБ (deps 8,5 ГБ, build 2,3 ГБ, incremental 1,9 ГБ,
    examples 295 МБ — отладочные пробы locks_probe времён 1.11.1);
  - target\release — 8,2 ГБ (deps 6,9 ГБ, build 1,3 ГБ);
- builds\ — 290 МБ: 38 релизных exe (по ~8,1 МБ, версии 1.0.1–1.12.1)
  + 2 сетапа + скриншот;
- node_modules\ — 137 МБ;
- backups\ — 30 МБ (8 зипов исходников — ротация по конструкции backup.ps1);
- .git — 13 МБ; dist\ — 8,9 МБ; весь исходный код вместе (src, src-tauri\src,
  scripts, CARDS, images, docs) — меньше 2 МБ.

Почему target разросся до 22 ГБ:
- это кэш cargo, он в .gitignore — git его не хранит и он не нужен для
  клонирования проекта;
- cargo никогда не удаляет старые артефакты: каждое изменение исходников даёт
  новые копии с content-хешем, старые остаются. За ~40 релизов (1.0.1→1.12.1)
  и десятки dev-сборок накопились: 41 устаревшая копия al_navi-*.exe в
  release\deps, ~7 копий собственного rlib (libal_navi_lib) в debug\deps;
- debug-сборки не стрипнуты и несут полные отладочные символы: debug-exe
  приложения — 295 МБ за штуку, собственный rlib — 155 МБ за копию;
- главные тяжеловесы — крейты windows / webview2-com (обвязка Windows API для
  Tauri): крейт windows весит 91–121 МБ на каждый хеш, а хешей по ~6 в debug
  и в release (rlib + rmeta) — только на него приходится порядка 2 ГБ;
- для сравнения: финальный релизный exe — 8,1 МБ (стрипнутый). Всё остальное
  в target — промежуточный кэш для быстрых пересборок.

Вывод: ничего лишнего или сломанного в проекте нет — исходники < 2 МБ, история
git 13 МБ, бэкапы 30 МБ. «25 ГБ» — это цена локальных сборок Tauri/Rust 
Windows (debug + release + инкрементальные кэши за 5 дней интенсивной работы).

    папка старта последнего поиска), корень последнего поиска остался лишь последним фолбэком,
    когда ни одна панель не даёт локального пути. Маска/текст/опции/даты/размеры восстанавливаются
