## Задача
`@phosphor-icons/web` подключён через `@import "@phosphor-icons/web/duotone"`
и `regular` в `src/app.css`; их style.css объявляет @font-face сразу в 4
форматах (woff2, woff, ttf, svg). WebView2 (Chromium) всегда берёт первый
поддерживаемый формат — woff2 — остальные форматы никогда не запрашиваются,
но vite честно копирует их в `dist/assets/`, а Tauri встраивает всё
содержимое dist в exe. Итог по сборке 1.12.10: Phosphor woff 488+567 KB,
ttf 488+567 KB, svg 2996+1749 KB — суммарно ~6.8 МБ мёртвого веса в exe и
установщике (при том что реально используемый woff2 — сотни KB). Заодно
проверить fontsource-шрифты (nunito/jetbrains-mono) на тот же паттерн.
Решение на выбор исполнителю: переопределить @font-face только на woff2
(классы .ph* оставить от пакета), маленький vite-плагин, отсекающий лишние
url() из CSS при сборке, или иной надёжный способ. Важно: иконки обоих
начертаний (regular + duotone) должны продолжать работать в WebView2.

## Критерии готовности
- [x] `dist/assets` не содержит ttf/svg вариантов Phosphor (и woff, если woff2 остаётся), exe и Setup легко на ~5–6 МБ — цифры до/после в журнале
- [x] Иконки regular и duotone рендерятся: проверка скриншотами заголовка/панелей/диалога и F1 (там duotone-иконки секций) в релизном exe
- [x] `npm run build` без новых предупреждений; svelte-check 0 ошибок; vitest зелёный
- [x] Дымовой e2e-smoke на реальном exe зелёный
