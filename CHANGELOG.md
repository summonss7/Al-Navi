## 1.14.0 — 2026-10-10

- **Колоночное (вертикально-блочное) выделение в редакторе** (карточка
  alnavi-034). `Shift+Alt+↑/↓` растят блок по строкам, `Shift+Alt+←/→` меняют
  ширину (с переходом через якорь — курсоры перекатываются на левый край),
  `Shift+Alt+Home/End` — ширина до начала/конца строки, `Shift+Alt+PgUp/PgDn` —
  блок растёт страницей (до краёв документа). Короткая строка даёт пустой ряд,
  как в FAR. Работает и в редакторе F4, и в read-only вьювере F3 (только
  копирование).
- Реализовано поверх множественной выборки CodeMirror (по диапазону на
  строку): **копирование** склеивает ряды переводами строк — пустые ряды
  остаются на месте, блок не съезжает при вставке (свой clipboard-хендлер:
  встроенный CM-серилизатор пустые диапазоны пропускает); **вырезание и
  Delete** удаляют фрагмент в каждой строке, пустые ряды не трогают —
  стандартный delete на пустом диапазоне съел бы перевод строки и склеил бы
  строки; **ввод текста** заменяет блок в каждой строке (нулевая ширина =
  классический мульти-курсор: печать идёт во все строки разом); плагины F11
  (регистр, раскладка) работают по каждому ряду. Обычное движение каретки
  (стрелки, Home/End, PgUp/PgDn, клик) сворачивает блок в одиночный каретка
  (семантика FAR), любое редактирование завершает режим. Для этого включён
  фейсет `allowMultipleSelections` (без него CM прореживает любую выборку до
  главного диапазона) — попутно мульти-курсор стал доступен расширениям.

- **SFTP-клиент — первый шаг V2 из ROADMAP** (карточка alnavi-014). Панели,
  командная строка и менеджер сайтов понимают `sftp://user@host:port/dir`
  наравне с `ftp://`: листинг (`F3` просмотр, текст/hex), правка с
  сохранением на сервер (`F4`/`F2`), `F7` — каталог, `F5`/`F6` —
  копирование/перенос с прогрессом (в том числе SFTP↔диск и SFTP→SFTP
  через временный файл), `F8` — удаление, `Shift+F6` — переименование —
  всё через общую очередь операций с паузой/отменой/фоном и
  конфликт-диалогами. Обрыв соединения — ретрай на свежем SSH-соединении;
  ошибки сети — диалогом, панель не блокируется. Крейты **russh 0.46 +
  russh-sftp 2.4** (оба Apache-2.0, чистый Rust — крипта на RustCrypto,
  без ring/openssl/C-сборки) — сборка на MSYS2 GNU-тулчейне остаётся
  оффлайн-совместимой с локальным cargo-кэшем (крейты скачаны в кэш разово,

### 2026-10-04, 07:47 — Почему проект занимает ~25 ГБ (карточка alnavi-019)

Ответ на вопрос «почему проект занимает 25Гб».

Фактический замер (du): каталог D:\Al-Navi занимает 22 ГиБ = 23,6 десятичных ГБ;
Проводник показывает «размер на диске» (округление кластерами вверх) — отсюда
«~25 ГБ». Суть не в точном числе: 99,5% объёма проекта лежит в одном каталоге
src-tauri\target — кэше компилятора Rust.

Разбивка по каталогам (сверху вниз):
- src-tauri\target — 22 ГБ. Из них:
  - target\debug — 14 ГБ (deps 8,5 ГБ, build 2,3 ГБ, incremental 1,9 ГБ,
    examples 295 МБ — отладочные пробы locks_probe времён 1.11.1);
  - target\release — 8,2 ГБ (deps 6,9 ГБ, build 1,3 ГБ);
- builds\ — 290 МБ: 38 релизных exe (по ~8,1 МБ, версии 1.0.1–1.12.1)
  + 2 сетапа + скриншот;
- node_modules\ — 137 МБ;
- backups\ — 30 МБ (8 зипов исходников — ротация по конструкции backup.ps1);
- .git — 13 МБ; dist\ — 8,9 МБ; весь исходный код вместе (src, src-tauri\src,
  scripts, CARDS, images, docs) — меньше 2 МБ.

Почему target разросся до 22 ГБ:
- это кэш cargo, он в .gitignore — git его не хранит и он не нужен для
  клонирования проекта;
- cargo никогда не удаляет старые артефакты: каждое изменение исходников даёт
  новые копии с content-хешем, старые остаются. За ~40 релизов (1.0.1→1.12.1)
  и десятки dev-сборок накопились: 41 устаревшая копия al_navi-*.exe в
  release\deps, ~7 копий собственного rlib (libal_navi_lib) в debug\deps;
- debug-сборки не стрипнуты и несут полные отладочные символы: debug-exe
  приложения — 295 МБ за штуку, собственный rlib — 155 МБ за копию;
- главные тяжеловесы — крейты windows / webview2-com (обвязка Windows API для
  Tauri): крейт windows весит 91–121 МБ на каждый хеш, а хешей по ~6 в debug
  и в release (rlib + rmeta) — только на него приходится порядка 2 ГБ;
- для сравнения: финальный релизный exe — 8,1 МБ (стрипнутый). Всё остальное
  в target — промежуточный кэш для быстрых пересборок.

Вывод: ничего лишнего или сломанного в проекте нет — исходники < 2 МБ, история
git 13 МБ, бэкапы 30 МБ. «25 ГБ» — это цена локальных сборок Tauri/Rust 
Windows (debug + release + инкрементальные кэши за 5 дней интенсивной работы).

Как освободить место (по желанию; эта задача — только анализ, ничего не удаляла):
- полностью: `cd src-tauri && cargo clean` — освободит все 22 ГБ; следующая
  сборка пересоберёт с нуля (~5–10 минут на release);
- мягко: удалить только src-tauri\target\debug — освободит 14 ГБ; релизные
