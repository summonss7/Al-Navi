## Задача
Обнаружено при работе над карточкой alnavi-006 (E2E на реальном exe).

Если приложение закрыть свёрнутым (в том числе `taskkill` из
scripts/build-release.sh по запущенному свёрнутому exe), в `%APPDATA%\al-navi\window.json`
сохраняется геометрия свёрнутого окна: `{"w":181,"h":24,"x":-32000,"y":-32000}`
(−32000 — куда Windows паркует минимизированные окна). При следующем запуске
`winstate.rs::restore_and_show` применяет размер (проверка только `w>0 && h>0`),
а позицию отбрасывает (она вне мониторов) — в итоге окно открывается щелью
181×24 в дефолтной позиции. У пользователя 03.10.2026 window.json находится
именно в таком состоянии.

Нужно:
- при сохранении геометрии (src/lib/windowState.ts) не писать размеры/позицию
  «свёрнутого» окна (фilter по аномалиям: w/h меньше минимальных, позиция
  −32000 и т.п.);
- при восстановлении (src-tauri/src/winstate.rs) клампить размер к разумному
  минимуму (например, 480×320), а не только `w>0 && h>0`.

## Критерии готовности
- [x] Закрытие приложения свёрнутым не портит window.json (сохраняется последняя нормальная геометрия)
- [x] restore_and_show клампит абсурдные сохранённые размеры/позицию к безопасным значениям
- [x] Проверено E2E или ручной проверкой (описано в отчёте в promt.txt)
- [x] Коммит с осмысленным сообщением
